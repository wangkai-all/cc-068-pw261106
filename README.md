# 本地工时数据整理

一个**完全本地化**的打卡数据整理工具：导入多种格式的打卡文件，按员工与薪资周期汇总正常工时、
加班、缺卡与跨夜班次。所有数据仅写入本地 SQLite，**不连接薪资系统或任何外部服务**。

## 快速开始

```bash
# 仅需 Python 3.11+（标准库，无第三方依赖）
python3 -m backend.server            # 默认 http://127.0.0.1:8765

# 造四份不同格式的样例文件（csv/tsv/json/xlsx，含 DST、跨夜、缺卡、冲突）
python3 tools/make_samples.py

# 对已启动的服务做端到端冒烟（预览→提交→冲突→补卡→重算→导出）
python3 tools/smoke_test.py

# 单元测试（21 个，覆盖 DST/缺卡/跨夜/去重/冲突/补卡/重算/HTTP API）
python3 -m unittest discover -s backend/tests -t .
```

数据默认存于 `data/timesheet.db`，可用环境变量 `TIMSHEET_DATA_DIR` 覆盖。

## 业务规则（关键约定）

### 时间与夏令时（DST）
1. 每条打卡先按**来源配置的 IANA 时区**解释为本地时间，再转 UTC 存储。
2. 班次时长一律按 **UTC 实际流逝分钟**计算，因此切换日天然得到差异：
   - 春季跳变夜（时钟跳过 1 小时）跨夜班会少 1 小时；
   - 秋季回拨夜（时钟重复 1 小时）跨夜班会多 1 小时。
3. **春季缺口时间**（本地时间不存在，如纽约 02:30）：按跳变前偏移换算 UTC，并登记
   `nonexistent_time` 问题，绝不静默改时间。
4. **秋季模糊时间**（同一本地时间出现两次）：按 `fold_policy` 解释
   （`first`=夏令时实例，默认；`second`=冬令时实例），并登记 `ambiguous_time` 问题。
5. 班次两端 UTC 偏移不同即标记 `dst_crossing`。

### 跨夜班次与归属日期
- 以**上班打卡的本地日期**作为班次归属工作日 `work_date`；
- 下班本地日期晚于上班日期即标记 `overnight`。

### 缺卡（绝不按零工时）
- 缺少下班（或上班）时间的班次 `total_minutes` 为 **NULL**，不计任何工时，
  只产生 `missing_punch` 问题；补卡并重算后才计入。
- 连续两张上班卡、有下班无上班等情况分别登记缺卡/未配对问题。

### 加班
- 按日规则：日工时超过「每日正常工时上限」（默认 480 分钟）的部分计加班。
- 超长班次（默认 >960 分钟）额外产生 `long_shift` 警告。

### 薪资周期
- 支持自然月 `monthly`、半月 `semimonthly`（1–15 / 16–月末）、按周 `weekly`（可设周起点）。

### 幂等与去重
- **文件级**：同一来源相同内容哈希（SHA-256）的文件只能成功提交一次，重复提交直接拒绝。
- **行级**：原始行内容哈希已存在则跳过，绝不重复计时。

### 冲突处理
- 同一员工同一工作日出现多套互斥班次（常见于多来源）→ 自动成组挂起，
  **解决前组内班次全部排除在工时汇总之外**；
- 界面列出每套班次的**原始行**供人工核对，选择保留哪一套后重算，决议留痕。
- 配对严格按 `(员工, 来源)` 各自独立，避免跨来源交错误配。

### 补卡与重算
- 手工补卡独立标记（`manual=1`），映射重算时保留，并在员工追溯中可见。
- 修订字段映射后可按来源重算受影响员工/周期；每次映射保存都生成 `mapping_versions` 版本。
- 作废批次会移除其原始行与归一化打卡并自动重算受影响员工。

## 两阶段导入

1. **预览**：上传后仅在内存解析，逐行展示「来源员工号 → 内部员工号、打卡类型、本地时间、
   DST 标记、去重、错误/警告、原始行」，不写任何数据。
2. **确认写入**：预览无误后才生成本地批次（`batches`），原始行逐行留存（`raw_rows`）。

## 数据模型（SQLite）

| 表 | 作用 |
|---|---|
| `source_configs` / `mapping_versions` | 来源格式、时区、字段映射及版本历史 |
| `employee_alias` | 各来源员工编号 → 统一内部员工号 |
| `import_files` | 文件登记与内容哈希（文件级幂等） |
| `batches` / `raw_rows` | 本地批次与逐行原始数据 |
| `punches` | 归一化打卡（本地/UTC 时间、手工标记） |
| `shifts` | 计算出的班次（跨夜、DST、工时，缺卡为 NULL） |
| `conflict_groups` / `issues` | 冲突组与缺卡/DST/超长/未配对问题 |
| `adjustments` | 手工补卡与修订记录 |
| `period_summary` | 按员工×周期的派生汇总（重算重建） |
| `build_runs` / `settings` | 重算留痕与全局规则 |

## 目录结构

```
backend/   标准库实现：db / timecalc(DST,周期) / mapping / parsers(csv,tsv,xlsx,json)
           engine(导入,配对,冲突,重算,汇总) / exports(CSV) / server(HTTP+静态)
frontend/  原生 ES Module 单页（无构建步骤）：导入预览、批次、汇总、问题补卡、
           冲突处理、来源映射、员工追溯
tools/     样例生成器与端到端冒烟脚本
samples/   生成的四种格式样例文件
data/      运行时 SQLite（git 忽略）
```

## 支持的文件格式

- **CSV / TSV**：自动识别分隔符与表头行，UTF-8/GBK 编码。
- **XLSX**：标准库 `zipfile+xml` 解析，支持共享字符串、内联字符串与 Excel 日期序列号。
- **JSON**：对象数组，兼容 `{"records":[...]}` 包裹；时间支持单列或日期+时刻两列。

时间字段支持 `2026-03-08 09:30`、`2026/03/08 09:30:00`、`2026年03月08日 09:30`、
ISO 等多种常见写法。
